# Aether Bedrock Mobs Reborn：基于当前 1.20.1 修复版的 1.21.1 NeoForge 迁移计划

## 当前基线

- 迁移工作树：`E:\模组\发cf的模组\生物\Aether Bedrock Mobs Reborn\1211 neoforge Aether Bedrock Mobs Reborn`
- 分支：`port/1211-neoforge`
- 来源：当前 1.20.1 Forge 工作区的完整工作树快照，包含最新未提交修复、资源和文档。
- 1.20.1 主工程保持原状，迁移分支不再从旧的 1211 半成品继续。
- 当前盘点：49 个 Java 文件、627 个资源文件、21 个 Java 文件直接使用 Forge API。

## 迁移原则

1. 保留当前 1.20.1 的全部行为、资源、Boss 技能、两阶段艾瑟龙、技能实体、粒子、音效、创造物品栏、刷怪和 GeckoLib 动画。
2. 不通过删功能、替换为临时占位实体或恢复已合并的旧蝴蝶 ID 来规避 API 适配。
3. 天境按可选依赖设计：不在 NeoForge 元数据中声明强制依赖；代码、数据生成和运行时注册不得在缺少天境时直接解析其注册表对象。
4. 每完成一阶段先做源码/API核对和最小静态验证；客户端仍不自动启动，服务端仅在迁移验收阶段按用户要求启动。

## 阶段一：冻结并核对 1.20.1 基线

- 核对主工程当前 `git diff`、未跟踪文件和最近修复，形成迁移输入清单。
- 逐项记录实体注册 ID、物品/方块 ID、粒子、音效、自然生成、Biome Modifier、结构和资源路径。
- 重点确认刚修复的实体行为、Boss 技能时间轴、装备属性、tooltip、蝴蝶颜色变体和自然生成权重不被迁移过程覆盖。

## 阶段二：NeoForge 构建骨架

- 将 ForgeGradle、Forge 47、Java 17 和 `mods.toml` 改为 NeoForge UserDev、NeoForge 21.1.233、Java 21 和 `neoforge.mods.toml`。
- 调整 `runs`、资源处理、发布组件和 GeckoLib/JEI 开发依赖坐标。
- 只保留 NeoForge、Minecraft 和 GeckoLib 的强制元数据依赖；JEI、天境不写入强制依赖表。
- 骨架完成后仅做配置、JSON 和依赖坐标静态核对，不自动启动客户端。

## 阶段三：注册与入口 API

按顺序迁移入口和注册类：

1. `AetherBedrockMobsReborn.java`
2. `registry/ModBlocks.java`、`ModItems.java`、`ModEntities.java`
3. `ModParticles.java`、`ModSounds.java`、`ModCreativeTabs.java`
4. 方块、物品和特殊刷怪器中使用的 Forge 扩展接口

每个注册表改动都要保持原 ID 和注册顺序语义，并确认 1.21.1 的数据组件、创造物品栏和 ToolAction API。

## 阶段四：事件、实体和网络

- 将 Forge 事件包、事件总线、客户端注册事件逐项改为 NeoForge API。
- 迁移 `RebornMobEntity`、Boss 技能实体、投射物实体和 `NagaPart` 的追踪、生成包、同步数据与 NBT。

- 保留当前伤害、击退、冷却、粒子和音效时间轴；遇到 API 差异时按源码/依赖签名改写，不做功能降级。

## 阶段五：客户端与资源

- 迁移 GeckoLib 4.8.4 的 NeoForge 初始化、模型、动画和渲染器注册。
- 迁移粒子提供器、实体渲染器、盔甲模型和客户端事件。
- 逐项校验资源路径、模型父级、纹理、音效、语言、刷怪蛋、Biome Modifier、结构集和战利品表。
- 对 1.21.1 数据包格式变化做逐文件解析，不能只依赖批量替换。

## 阶段六：天境缺失场景

- 将天境实体、群系、维度和标签引用集中到安全的运行时查询边界。
- 没有天境时，模组应能完成加载；相关自然生成、结构或交互按已定义的空结果处理。
- 有天境时，恢复完整生成和交互，并验证可选依赖不会被发布 JAR 打包。
