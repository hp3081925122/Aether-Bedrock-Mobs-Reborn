# Aether Bedrock Mobs Reborn — 重写设计文档

> 目标：在 Minecraft 1.20.1 Forge 上，以可审计的功能证据为基础重写 Aether Bedrock Mobs，产出独立维护的 Aether Bedrock Mobs Reborn。
>
> 范围：功能等价重写、资源和数据重建、Aether/GeckoLib 接入、服务端与客户端验证。  
> 非目标：直接搬运 MCreator 生成 Java、在本轮兼容其他 Minecraft 版本或加载器、用删减功能换取快速迁移。

## 1. 背景与问题

原项目页面描述了 Aether 维度中的新地牢、Boss、环境生物、武器和结构，用户确认原实现来自 MCreator，生成代码不适合作为高版本维护基础。当前目标工作区为空，也没有可直接迁移的 Git、Gradle 或 MCreator 工程；但已取得公开发布的 `aethermobs-1.5.0-forge-1.20.1.jar`，可以进行只读功能和资源取证。因此本项目的技术路线是“以正式 JAR 为证据的功能和资源重写”，而不是传统的版本迁移。

页面还说明原项目面向 Minecraft 1.20.1 Forge，依赖 Aether 和 GeckoLib；这些信息可以作为初始兼容目标，但依赖的确切版本仍需从原 JAR、原工程或目标整合包确认。

## 2. 方案与核心原则

### 2.1 证据优先

先建立内容清单和证据索引。每个实体、Boss、物品、结构、生成规则和动画至少关联一种来源；来源不足的条目进入“待确认”，不在代码中凭空补齐。

### 2.2 干净架构

使用标准 Forge 1.20.1 工程重新组织：注册表集中管理，实体行为放在独立实体类，客户端渲染与模型动画隔离，世界生成和结构数据使用数据驱动方式，事件接线集中在生命周期或事件订阅层。旧 MCreator 类名、方法层级和无效生成器辅助类不作为架构约束。

### 2.3 逐层验证

每一层先通过最小验证再进入下一层：工程骨架编译 → 注册表与资源加载 → 单个实体 → Boss 战斗 → 结构和生成 → 服务端/客户端集成 → 正式构建。客户端实际游玩属于独立运行验收，不把 Gradle 成功等同于功能完成。

## 3. 架构与关键决策

### 3.1 冻结模块边界

- 模组 ID 冻结为 `aether_bedrock_mobs_reborn`；不承诺旧存档的原注册 ID 兼容。
- Java 根包冻结为 `com.aetherbedrockmobsreborn`。
- 资源命名空间与模组 ID 一致。
- GeckoLib 为硬依赖，版本冻结为 4.8.4；Aether 已改为可选依赖，资源通过本模组的可选 Aether 生物群系标签接入。
- 可选依赖不写入模组依赖声明；缺失 Aether 时相关生物群系生成与结构生成自动跳过。

### 3.2 内容流

```mermaid
flowchart LR
    A[证据与功能清单] --> B[注册表契约]
    B --> C[实体与物品实现]
    B --> D[结构与世界生成数据]
    C --> E[客户端渲染与动画]
    D --> F[数据与事件集成]
    E --> F
    F --> G[构建与运行验收]
```

### 3.3 重写单元

| 单元 | 责任 | 不负责 |
|---|---|---|
| 注册层 | 统一注册实体、物品、方块、结构相关对象 | 实体 AI 细节、客户端渲染 |
| 实体层 | 属性、AI、伤害、召唤、掉落和 Boss 阶段 | 直接修改其他单元的注册表 |
| 客户端层 | GeckoLib 模型、动画控制器、渲染器和客户端事件 | 服务端状态持久化 |
| 世界生成层 | 地牢结构、放置、生成条件和维度限制 | UI 或战斗数值 |
| 数据层 | 战利品、配方、标签、进度和本地化 | 运行时实体逻辑 |
| 集成层 | Aether 生命周期、事件、配置和兼容边界 | 隐藏未记录的内容增删 |

## 4. 依赖

### 硬依赖

- Minecraft 1.20.1。
- Forge 版本冻结为 47.4.23。
- Aether 使用目标整合包已确认的 CurseMaven 文件 `6134920`。
- GeckoLib 使用 `4.8.4`。原 JAR 虽将 GeckoLib 标为非必需，但其模型和动画资源实际使用 GeckoLib；重写版不能照搬这个可选标记。

### 可选依赖

当前没有已确认的可选依赖。后续若发现其他扩展兼容需求，应通过运行时隔离处理，不写入必需依赖声明。

## 5. 接口与契约（S1 冻结）

以下内容在 S0 证据恢复后冻结，后续任务只能读取，不能在同一阶段自行改名：

- 模组 ID、Java 根包、资源命名空间。
- 每个注册对象的稳定 ID、显示名和来源证据。
- 实体与客户端渲染器的对应关系。
- 结构文件命名、结构标签和生成入口。
- 配置键、默认值、语言键和数据迁移规则。
- 服务端状态同步方式，以及 Boss 阶段和召唤条件的状态字段。

## 6. 风险与边界

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 没有原始工程，功能细节缺失 | 高 | S0 建立证据清单；缺失项标记待确认，不以猜测替代 |
| MCreator 资源 ID 与目标架构不一致 | 高 | 先导出注册表和资源索引，再统一映射 |
| Aether/GeckoLib API 与原环境不同 | 高 | 查看目标依赖源码和缓存 JAR，冻结版本后再写接入代码 |
| 结构和世界生成难以从页面复原 | 高 | 优先获取结构文件或正式 JAR；无法复原的条目单独列出 |
| 客户端模型动画与服务端行为不同步 | 中 | 服务端状态字段先定契约，客户端只消费同步状态 |
| 误把构建成功当成玩法完成 | 中 | 单独维护构建、启动、世界生成、战斗和正常退出测试记录 |
| 旧存档兼容范围不明 | 中 | 默认视为新模组；只有用户明确要求时才设计迁移映射 |

**边界：** 本轮不承诺旧模组存档兼容、不承诺缺失证据的内容完全复原、不自动启动客户端进行游玩测试，也不通过削减实体或结构来降低迁移难度。
